## 4. 风险 + 回滚

### 4.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| PyPI `pandaone-guard` 名被抢注 | **致命** —— 无法迁移 | 已经在 https://pypi.org/project/pandaone-guard/ 验证返回 404,**确认未被占**(2026-09-13 检查) |
| Trusted Publisher 配错(workflow name 写错) | publish.yml 推送 tag 后 PyPI 401 | publish.yml 的 workflow_dispatch input 也提供 token 模式 fallback(PR #16 加的) |
| 现有 `pandax-guard` 用户升级 v0.7.6 后找不到包 | 用户困惑 | release notes / README 写明"两个名字共存",只要 GitHub 上 `pandax-guard` 项目还活,旧 `pip install pandax-guard` 仍然 work |
| v0.7.6 与 v0.7.5 测试数据冲突 | 升级链路出问题 | 测试用全新 venv 验证 `pip install pandaone-guard` + `pandaone --help` |

### 4.2 回滚

如果 v0.7.6 发布后发现问题:

1. **不要删 PyPI 项目** —— PyPI 不允许删已发布的版本,只能 yank(隐藏)
2. **不要删 tag** —— 改 release 为 `pre-release` 标记
3. **git revert PR #22 + PR #23** —— 回到 v0.7.5 状态
4. **发 v0.7.6.1 hotfix** —— 修问题后重发

PyPI 上 `pandax-guard` 项目**不动**,继续 serve v0.7.4 给不愿意升级的用户。
