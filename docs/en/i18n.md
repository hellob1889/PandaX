# Internationalization (i18n)

Since v0.7.0, Pandaone AI Agent natively supports multiple languages (zh-CN / en). This guide explains the translation system's design principles, how to add new languages, and how to contribute translations.

## 1. Design Principles

### First Principles

- **Zero dependency**: No gettext / babel; uses built-in `dict` data structure
- **3-layer priority**: CLI `--lang` > user preference `~/.pandaone/config.json` > OS auto-detection
- **Bilingual static strings**: Right-click menu registry / `.desktop` files are system-level static entries that can't be dynamically switched, so we use "Chinese + English side-by-side"
- **README kept untranslated**: README.md is the project's core document, kept in source language for single source of truth

### Adversarial Review

| Attack | Mitigation |
|---|---|
| Malicious .mo file injection | Translations embedded in `pandaone/i18n.py` Python dict, no external file reads |
| Modifying `~/.pandaone/config.json` | Only affects display language, not security logic |
| Spoofed locale env vars | Strict whitelist (zh-CN / en only) |
| Missing translation key causes crash | `t()` has 3-level fallback (current lang → en → raw key) |

## 2. CLI Usage

```bash
# Auto-detect OS language (recommended)
pandaone                      # Chinese system → Chinese; others → English

# Explicit language (overrides auto)
pandaone --lang=zh-CN         # Force Chinese
pandaone --lang=en            # Force English

# Specify language for right-click menu install (affects PS1 script UI)
pandaone install-context --lang=en

# Check current effective language
python -c "from pandaone import i18n; print(i18n.get_lang())"
```

## 3. Adding a New Language

### Step 1: Add entry to `TRANSLATIONS`

Edit `src/pandaone/i18n.py`, add a new key to the `TRANSLATIONS` dict:

```python
TRANSLATIONS = {
    "zh-CN": {...},  # existing
    "en": {...},     # existing
    "ja": {          # NEW: 日本語
        "_lang_name": "日本語",
        # ... copy all keys from zh-CN, translate one by one
        "ok_locked_n": "{n} files locked...",
        ...
    },
}
```

### Step 2: Check coverage

```python
from pandaone import i18n
report = i18n.coverage_report()
print(report["ja"])
# {'total': 149, 'present': 149, 'missing': [], 'missing_pct': 0.0}
```

### Step 3: Extend CLI `--lang` option

Edit `src/pandaone/cli.py` `build_parser`:

```python
parser.add_argument("--lang", choices=["zh-CN", "en", "ja"], default=None, ...)
```

### Step 4: Extend auto-detection (optional)

Edit `src/pandaone/i18n.py` `_detect_os_language()`:

```python
if lang_lower.startswith("ja"):
    return "ja"
```

### Step 5: Test

```bash
pandaone --lang=ja status
```

## 4. Translation Key Naming Convention

| Prefix | Meaning | Example |
|---|---|---|
| `ok_*` | Success message | `ok_locked_n`, `ok_written` |
| `err_*` | Error message | `err_fingerprint_mismatch` |
| `warn_*` | Warning | `warn_lock_failed` |
| `info_*` | Info | `info_fp_generated`, `info_os_detected` |
| `status_*` | `pandaone status` output | `status_l1`, `status_total` |
| `write_reject_*` | `pandaone write` rejection reason | `write_reject_target_not_exist` |
| `log_*` | `pandaone log` output | `log_header`, `log_field_*` |
| `git_*` | `pandaone install-git` | `git_probe_found` |
| `hook_*` | `pandaone install-hook` | `hook_installed` |
| `watch_*` | `pandaone watch` | `watch_daemon_started` |
| `ci_*` | `pandaone ci` | `ci_pass_all`, `ci_fail_n` |
| `menu_*` | Right-click menu (static) | `menu_init`, `menu_lock` |
| `macos_*` | macOS workflow dialog | `macos_choose_prompt` |
| `_*` | Internal helpers (also need translation) | `_stored`, `_current` |

## 5. Placeholders

Use Python `str.format()` placeholders:

```python
"ok_locked_n": "[OK] Locked {n} files (protected extensions: {exts})"
# Call: t("ok_locked_n", n=3, exts=".py,.json")
```

Consistent placeholder naming:

- `{n}` / `{m}` — Numbers (count / max)
- `{path}` / `{file}` / `{dir}` / `{root}` — File paths
- `{fp}` / `{stored}` / `{current}` — Fingerprint hash (truncated to 16 chars)
- `{err}` / `{e}` — Error message
- `{pid}` — Process ID
- `{cmd}` / `{path}` — Command string
- `{base}` / `{head}` — Git ref
- `{exts}` / `{text_exts}` / `{binary_exts}` — Extension list

## 6. Contributing Translations

1. Fork the repo
2. Edit `src/pandaone/i18n.py`
3. Run tests: `python -m pytest tests/test_i18n.py -v`
4. Run coverage: `python -c "from pandaone import i18n; print(i18n.coverage_report())"`
5. Submit PR, title format: `i18n: add XX translation (xx)` (e.g. `i18n: add Japanese translation (ja)`)

## 7. What NOT to Translate

| Content | Reason |
|---|---|
| README.md step lists (`Step 9` etc.) | Single source of truth, maintained by developers |
| Comments / docstrings | Code readability |
| ASCII art banner | Visual consistency |
| Git commit hashes | Hash values not translatable |
| Internal IDs (`audit_xxx`, `APPROVED` etc.) | Machine-readable fields |
| File names / paths | System-level identifiers |

## 9. Troubleshooting

### Q: I changed `~/.pandaone/config.json` but it doesn't take effect?

A: Check encoding (must be UTF-8 no BOM), JSON format (`{"lang": "en"}`). Delete the file and run `pandaone --lang=en` to regenerate.

### Q: Chinese Windows shows English?

A: Priority `--lang` > preference > auto. If you ran `pandaone --lang=en`, it persists preference. Delete `~/.pandaone/config.json` to reset auto-detection.

### Q: Added translation but still shows fallback?

A: Check key spelling (Python dict is case-sensitive). Run `coverage_report()` to see missing list.
